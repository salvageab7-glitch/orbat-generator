# 模式三 · 外部 Agent 快速上手（中文版）

> **适用模型**：DeepSeek-VL 系列、Kimi（moonshot 视觉型号）、豆包 Doubao-vision、Qwen-VL、GLM-4V 等**能直接看图**的中文模型。
> **不适用**：纯文本模型（如不带视觉的 deepseek-chat）。遇到这种情况走 §0 的替代路径。
> **对应版本**：orbat-cli v0.3.6。文档里的命令都在 `orbat-cli.exe` 所在目录执行。

---

## 0. 先用 30 秒判断你能不能干这活

| 你的能力 | 做法 |
|---|---|
| 能直接读图（多模态） | 按本文档走，你就是"识图引擎" |
| 只能读文字 | 让用户把编制表按缩进贴成文本，你只做「文本 → JSON」（跳过 §4 切块），其余流程完全一样 |
| 能读图但看不清小字 | 一定要切块（§4），不要硬看整图 |

模式三的全部意义：**这个软件不调用任何模型、不需要 API Key**，识图由你完成，软件只负责校验与出图。

---

## 1. 你在整条链路里的位置

```
用户给图 ──▶ 你（读图 → orbat.json） ──▶ orbat-cli（校验 / 审计 / 出图） ──▶ PNG + SVG
                    ▲                              │
                    └──── 红牌清单（exit 3）────────┘
```

三条铁律：

1. **不要调用 `generate`**：那是模式一/二（软件自己调模型），模式三没有 Key，会直接报错。
2. **JSON 由你写**，不要指望软件替你转写。
3. **出图必须联网**：调用 spatialillusions.com 的线上渲染器，本机需要 Node ≥ 24 与 Chrome/Edge。

---

## 2. 最小闭环（四条命令）

```bat
:: ① 取规则（第一次用时执行一次，把内容读进上下文）
orbat-cli.exe prompts --type tile --out 提示词.txt

:: ② 你按提示词读图，写出 orbat.json（格式见 §3）

:: ③ 校验：exit=3 表示有红牌，必须修完再出图
orbat-cli.exe validate orbat.json

:: ④ 出图：约 15-40 秒，返回 PNG / SVG 的绝对路径
orbat-cli.exe render --in orbat.json --out 成品名
```

`render` 的返回（stdout 单个 JSON）：

```json
{"ok":true,"command":"render","data":{
  "outputBase":"D:\\out\\成品名","png":"D:\\out\\成品名.png","svg":"D:\\out\\成品名.svg",
  "nodeCount":44,"ok":true,"error":null,"elapsedMs":14842}}
```

调用约定（所有命令一致）：stdout 只有一个 JSON；stderr 是日志；exit code `0` 成功 / `1` 执行失败 / `2` 参数错 / `3` 校验发现红牌。

## 3. JSON 契约（只认 3 个字段）

最小可用结构如下，**多余键会被忽略**，不用纠结渲染器的其他参数：

```json
{
  "options": {
    "sidc": "130310002111000000000000000000",
    "uniqueDesignation": "第2师",
    "additionalInformation": ""
  },
  "subOrganizations": [
    {
      "options": {
        "sidc": "130310001612110200000000000000",
        "uniqueDesignation": "第1机械化步兵营",
        "additionalInformation": "Holsworthy"
      },
      "subOrganizations": []
    }
  ],
  "commandLevels": "1"
}
```

| 字段 | 规则 |
|---|---|
| `options.sidc` | **必须 30 位数字**（构造见 §5）。不知道就先用最接近的，校验会指出问题 |
| `options.uniqueDesignation` | 单位名称/番号，**照抄图上的文字**，含型号，不要概括 |
| `options.additionalInformation` | 注释，驻地或职能短名；中文 ≤12 字、英文 ≤20 字母；可为空 |
| `subOrganizations` | 子单位数组，按图上的父子关系嵌套 |
| `commandLevels` | 只写在根节点，常用 `"1"`（紧凑）或 `"3"`；子节点不要写 |

补充：

- 层级只由**嵌套**表达，不要再写"上级/下级"之类的字段。
- `parse` 只报告节点数与层级（不做转换）；需要转成渲染器 7 键结构用 `normalize 编制.json --out render.json`。
- 导出给用户的 JSON **保留原文名称**，不要自己截断（渲染时才做长度适配）。

## 4. 大图切块（正确率的第一决定因素）

整图硬看是漏节点、错层级的主要来源。按下面判据决定：

| 条件 | 做法 |
|---|---|
| 长边 ≤ 4000 px 且 总像素 ≤ 3000 万 | 整图直接读 |
| 长边 > 4000 px 且宽高比 < 1.8（接近方形、字很小） | **必须切块**（软件内部也是这么切的） |
| 长边 > 4000 px 的宽图（宽高比 ≥ 1.8） | 可以整图；单位很多时建议切竖条，漏读率更低 |

切块参数（与软件内部一致，实测最优）：

- 每块覆盖原图 **2600 px**（沿长边方向切），相邻块 **重叠 12%**；
- 每块发送前缩放到**长边 1536 px**，文字仍然清晰；
- 横向展开的编制图**从左到右**切竖条；接近方形的密集图切横条。

切完逐块读，然后按这三条合并：

1. **同父同名** → 合成一个，保留子节点更完整的那份；
2. **跨块同名但父级不同** → 保留层级证据更充分的一份，另一份记入"待确认"；
3. **重叠区重复出现** → 正常现象，按名称去重，不要当成两个单位。

合并后必须回图核对一次：`JSON 节点数 = 各方块方框计数之和 − 重叠重复数`。对不上就说明漏了或多了。

### 名称与注释铁律（校验器会查）

- 名称照抄：`第1МТ-12反坦克炮连` 不能写成 `第1反坦克连`；
- 型号/口径/数量放注释，不放名称；
- 注释 ≤12 汉字（英文 ≤20 字母），不写指挥官姓名；
- 名称里禁止"空格 + 左括号"，括号内容移到注释；
- **营级及以上必须逐个建节点**，禁止 `×3` 合并；连、排级同构单位可合并；
- 图上没有的方框不要补，看不清的保留并在名称后标 `[?]`。

## 5. SIDC 速查（30 位）

```
1303 | 符号集 | 00 | 梯队 | 主实体 | 类型 | 机动 | 扇区 | 00000000
 4      2      2     2       6       2      2      2        8      = 30
```

| 梯队 | 码 | 主实体 | 码 |
|---|---|---|---|
| 班 | 12 | 司令部/指挥机构 | 110000 |
| 排 | 14 | 步兵（含轻步兵） | 121100 |
| 连 | 15 | 装甲/机械化(履带) | 121102 |
| 营 | 16 | 摩托化步兵 | 121104 |
| 团 | 17 | 步兵战车(IFV) | 121105 |
| 旅 | 18 | 装甲 | 120500 |
| 师 | 21 | 反坦克 | 120400 |
| 军 | 22 | 炮兵(通用) | 130300 |
| 集团军 | 23 | 自行火炮(履带) | 130301 |
| | | 炮兵侦察/观察 | 130400 |
| | | 迫击炮 | 130800 |
| | | 防空 | 130100 |
| | | 侦察 | 121300 |
| | | 监视/雷达站 | 121600 |
| | | 反情报 | 150200 |
| | | 电子战 | 150500 |
| | | 联络 | 110500 |
| | | 通信 | 111000 |
| | | 工兵 | 140700 |
| | | 勤务支援 | 160000 |
| | | 医疗/卫生 | 161300 |
| | | 军法署 | 160800 |

> 主实体语义以 spatialillusions 站点官方解释为准（2026-11-19 裁决）。注意：`121100`步兵、`121102`装甲机械化、`121104`摩托化、`121105`步兵战车是同族（`12110x`）的不同子类型——**前 5 位相同、末位不同**，别混用。`130301`自行火炮是旧版子码，站点当前表无此码但渲染器实测有图标，有效。

> ### ⛔ 修饰位全部禁用（2026-11-19 用户明令）
> 主实体 6 位之后的 **14 位必须全 0**（类型2 + 机动2 + 扇区2 + 保留8），**不允许任何小标志**（不写 `04`履带、`05`轮式、`41`火箭炮、`01`扇区）。载具/口径/火箭炮细节靠 `uniqueDesignation` 名称表达。
> 例：摩托化步兵=`130310001612110400000000000000`、自行火炮=`130310001613030100000000000000`、火箭炮=`130310001613030000000000000000`（站点无独立火箭炮码，靠名称区分）。
> `validate` 对修饰位非零只报 warn（不拦截），含旧修饰的历史文件仍可出图。

两个最常踩的坑：

- **符号集**：地面单位 `10`，直升机/无人机/固定翼 `01`（用错会渲染成方块）；
- **110000（指挥机构）禁止类型修饰 `98`**，否则整棵子树在图上消失。

示例：营级装甲步兵 = `1303` + `10` + `00` + `16` + `121102` + `00` + `00` + `00` + `00000000`。

## 6. 粘贴版系统提示词（可直接用作 system prompt）

```
你是 ORBAT 编制图转写引擎。输入一张编制图（或图块），输出严格三段，不要输出其他内容。

<观察>
方框计数：N          ← 这张图块里有几个独立单位方框，必须给数字
逐行列出关键单位（5-15 个）：名称 + 它连着谁
看不清的标 [?]
</观察>

<json>
{"options":{"sidc":"30位数字","uniqueDesignation":"图上原文名称","additionalInformation":"驻地或职能"},
 "subOrganizations":[...],"commandLevels":"1"}
</json>

<自检>
JSON 节点数：M（与方框计数 N 的差异及原因）
已删除（图上找不到方框）：...
待确认（标了 [?]）：...
</自检>

规则：
1. 只写图上真实画出的单位，不按编制惯例补全；图上画到营就停，不要建连。
2. 父子关系只看连线：直属分队（旅部连、通信连、工兵连等）与各营平级。
3. 名称照抄原文，型号/口径/数量放注释；注释 ≤12 汉字（英文 ≤20 字母）。
4. 营级及以上逐个建节点，禁止 ×3 合并。
5. SIDC 30 位：1303|符号集(10地面/01空中)|00|梯队|主实体|类型|机动|扇区|00000000。
6. 每个节点都要能在图上指到一个方框，指不出就删掉。
```

更完整的规则（含全部实体码表、计数锚、判据声明）用 `orbat-cli.exe prompts --type tile` 导出，以那份为准。

## 7. 质量回路

```
validate ──红牌──▶ 修 JSON ──▶ validate ──0 红牌──▶ audit ──▶ render
```

- `validate` 返回 `redCount / warnCount / issues[{level,path,message}]`，**exit=3 就是有红牌**。
- 常见红牌与修法：

| 红牌信息 | 含义 | 修法 |
|---|---|---|
| `SIDC 必须 30 位，当前 N 位` | 码拼接时漏段 | 按 §5 重拼，检查是否漏了符号集或 `00` |
| `110000(HQ) 禁止加类型修饰 98` | 指挥机构加了非法修饰 | 类型位改 `00` |
| `…是空中单位，符号集应为 01` | 直升机/无人机用了地面符号集 | 第 5-6 位改 `01` |
| `同一父节点下出现同名子节点` | 合并没去重 | 删掉冗余节点，子节点并入保留者 |
| `注释超长` | 超过 12 汉字 / 20 字母 | 删到上限内，驻地用简写 |
| `层级倒挂` | 子单位等级高于父单位 | 回图核对连线，改层级或改梯队码 |

- `audit --in 编制.json` 查"名称与 SIDC 自洽性"，返回 `sidcMismatches[{path,name,current,suggested,reason}]`。
  只在与名称层级明确冲突时采用 `suggested`；`2nd Division Postal Unit` 这类以母体名开头的名称**不要**改。
- 批量修用补丁，不要让模型重写整棵树：

```bat
:: 补丁文件 patches.json
:: {"patches":[{"path":"根/第1旅/第2营","sidc":"130310001612110200000000000000"}]}
orbat-cli.exe edit --in 编制.json --patches patches.json --out 编制_fixed.json
```

`path` 用 `/` 分隔，从根名开始（也可用 `根/...` 或 `root/...`），必须与树中的名称**逐字一致**；路径不命中会被跳过，不会破坏原文件。

---

## 8. 交付给用户什么

1. `编制.json`（原文名称，未截断）；
2. 出图产物 `*.png` / `*.svg`（路径用返回里的绝对路径）；
3. 一句话小结：**N 个节点 / 最深 D 层 / 红牌 0 / 待确认 K 处**，并列出待确认项；
4. 若做了切块：说明切了几块、重叠区怎么去重。

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `render` 返回 `未找到 node ≥ 24` | 没装 Node 或版本过低 | 装 Node 24+；完整版安装包自带 `bin\node.exe` |
| `render` 15 秒后超时/失败 | 站点不可达、浏览器被策略禁用、单位名过长 | 先 `selfcheck --smoke` 定位；把超长名称的括号内容移到注释 |
| `generate` 报"未配置 API Key" | 你误用了模式一/二的命令 | 模式三不要用 `generate`，用 §2 的流程 |
| `validate` 一直 exit=3 | 只修了一部分红牌 | 逐条对照 `issues`，改完再校验，直到 `redCount=0` |
| `edit` 报"路径全部未命中" | 名称里有空格/全半角差异 | 用 `audit` 或 `parse` 看实际名称，逐字复制 |
| 出图符号是空白方块 | SIDC 符号集或实体码错 | 查 §5，或 `audit` 看建议值 |

自检：`orbat-cli.exe selfcheck --smoke`（约 20 秒，真渲染一张 3 节点小图）。

## 10. 命令速查

| 命令 | 用途 |
|---|---|
| `prompts --type tile [--out 文件]` | 导出识图提示词 |
| `validate 编制.json` | 结构校验（红牌 exit=3） |
| `audit --in 编制.json` | 名称与 SIDC 一致性审计 + 跨父同名扫描 |
| `edit --in 编制.json --patches 补丁.json [--out]` | 批量改字段 |
| `edit --in 编制.json --path "根/第1旅/第2营" --name/--note/--sidc [--out]` | 改单个单位 |
| `normalize 编制.json --out render.json` | 转渲染器 7 键结构 |
| `render --in 编制.json [--out 基名]` | 出图（需要 Node ≥ 24 + 浏览器 + 联网） |
| `tutorial` | 打印软件内置教程（给人看的） |
| `selfcheck --smoke` | 出图链路自检 |

所有命令加 `--help` 看参数。
