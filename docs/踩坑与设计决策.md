# 踩坑与设计决策

> 记录实现过程中**实测验证过**的事实。每条都附证据来源，避免下次重新试错。

---

## 1. SIDC 主实体码的语义依赖符号集（最关键）

**事实**：同一个 6 位主实体码，在陆地符号集和空中符号集里含义完全不同。

| 符号集（位 4-5） | 完整前缀 | 同一码 `110400` 的含义 |
|---|---|---|
| `10` 陆地 | `13031000` | INFORMATION OPERATIONS（信息作战） |
| `01` 空中 | `13030100` | VERTICAL-TAKEOFF UAV（垂直起降无人机） |

**证据**：用 milsymbol 3.0.4 的 `meta` 命令解析两个码，`dimension` 分别为 Ground / Air。

**后果**：如果校验器只维护一张陆地码表，所有航空器节点都会被误报「码不合法」。

**处理**：`OrbatValidator` 先读位 4-5 判断符号集，再查对应的全量表
（`kLandEntityFull` 219 条 / `kAirEntityFull` 53 条，均由 `_tools/sidc_entities.json` 生成）。

## 2. 30 位 SIDC 的分段（0-based）

```
130310001612110400040100000000
│      │ │ │      │ │ │ └ 22-29 保留 = 00000000（8 个 0）
│      │ │ │      │ │ └── 20-21 扇区修饰
│      │ │ │      │ └──── 18-19 机动修饰
│      │ │ │      └────── 16-17 类型修饰
│      │ │ └───────────── 10-15 主实体
│      │ └─────────────── 8-9  梯队
│      └───────────────── 4-5  符号集（10 陆地 / 01 空中），6-7 = 00
└──────────────────────── 0-3  版本+上下文 = 1303
```

**易错点**：`13031000` 这个 8 位前缀已包含符号集，**往后数梯队从索引 8 开始**。
早期版本的代码把梯队读成 `substring(7,9)`，导致整条解析链错位。

## 3. Dart 的 `HttpClientRequest.write(String)` 按 Latin1 编码

**现象**：请求 system prompt（全中文）时抛
`Invalid argument (string): Contains invalid characters.`

**原因**：`write()` 走 `_IOSinkImpl._writeString` → `Latin1Codec.encode`，非 Latin1 字符直接失败。

**解决**：
```dart
final payload = utf8.encode(json.encode(body));
request.headers.contentLength = payload.length;
request.add(payload);   // 用字节流，不要用 write(String)
```

**教训**：这个 bug 在没有真实调用前完全看不出来——离线自检全过，一联网就崩。

## 4. `deepseek-flash` 默认开启思考模式

**现象**：HTTP 200，但 `choices[0].message.content` 是**空字符串**，
内容全在 `message.reasoning_content`，且 `finish_reason` 可能是 `length`。

**实测参数对比**：

| 参数 | 结果 |
|---|---|
| 不传 | content 空，内容在 reasoning_content，finish=length |
| `reasoning_effort: "low"` | **无效**，仍思考且被截断 |
| `reasoning: {effort: "low"}` | **无效** |
| `thinking: {"type": "disabled"}` | ✅ content 正常，finish=stop |

**处理**：`DeepSeekConfig.disableThinking = true`（默认），只在需要推理时才开。

## 5. 模型能力（2026-11 实测自 `/models` 接口）

| 模型 | 上下文 | 最大输出 | 输入模态 |
|---|---|---|---|
| `deepseek-flash` | 1,048,576 | 393,216 | **text, image** |
| `deepseek-v4-pro` | 1,048,576 | 393,216 | text |

编制图识别必须用 `deepseek-flash`——只有它支持图像输入。

实测成本参考：识别一张 25 节点的编制图，约 4 秒，输入约 1.5k token（图片折算），
单次成本在**几分钱**量级。

## 6. 出图：只能走线上渲染器

- spatialillusions.com 的 Battle Staff Tools 是**闭源商业软件**，ORBAT 排版算法未公开。
- 底层 `milsymbol.js` 是 MIT，但排版层不开源，开源替代（ORBAT Mapper）风格不同，做不到 1:1。
- 因此出图固定调用 `_tools/render_orbat.js`（CDP 驱动 Chrome 打开线上页、导入 JSON、导出 SVG+PNG）。

**硬约束**：node 主版本必须 ≥ 24。低版本会**无界挂起**（画布渲染完但进程永不退出）。
脚本里已加守卫，版本不符直接 `exit 2`。

---

## 7. `000000` 是合法的项目约定码

milsymbol 标准表里没有 `000000`，但项目规范明确要求
「不确定主实体时一律用 `000000`（通用指挥标志）」。

**处理**：校验器对 `000000` 放行，不报「不在标准表」。

同理，`110000`（HQ）**绝不能**加类型修饰 `98`——会导致该节点整棵子树在渲染时消失。

## 8. 自我修复循环

模型生成的 SIDC 常有系统性错误（实测第一次生成全部变成 32 位）。
让模型「一次到位」不可靠，但如果把**本地校验器发现的具体错误**回传给它，
修复成功率显著提高。

`OrbatPipeline` 实现了最多 2 轮修复：生成 → 校验 → 有红牌则回传错误清单 → 重新校验。

## 9. 中文路径注意事项

Windows 用户名含中文（如 `C:\Users\胡宇晨`）会让部分工具链出问题。
Flutter SDK 因此装在 `C:\flutter`（纯 ASCII 短路径）。
配置文件放 `%APPDATA%\OrbatGenerator`（路径仍含中文，但纯 Dart 读写无问题）。

## 10. 目录写权限不可假设（出图"静默卡住"的根因）

**现象**：点「出图」后界面毫无反应，等两分钟也没有任何报错。

**根因链**：
1. `Directory.systemTemp.createTemp()` 在某些进程上下文下抛
   `PathAccessException: 拒绝访问 (errno = 5)`；
2. 这行原本在 `try` 之外，异常一路抛到 Flutter 的异步错误处理器；
3. UI 上没有任何提示，用户只看到"没反应"。

日志文件（`%APPDATA%\...\logs\render-*.log`）写入也会以
`Unhandled Exception` 形式失败——`IOSink` 的错误是异步抛出的，
`try-catch` 包住 `writeln` 抓不到。

**修复**：
- `resolveWritableDir()` 依次试「系统 Temp → 应用数据目录 → 当前目录 → exe 同级」，
  每个候选都**写探针文件**验证（`exists` 不代表可写），全失败则明确报错。
- 日志改为**同步追加写**并整体 try-catch，写不了就放弃日志，不影响出图。
- 出图前单独探测**输出目录**可写性，给出「请换一个保存位置」的人话提示，
  而不是等脚本写 SVG 时报 `EPERM`。
- 通过环境变量 `ORBAT_WORK_DIR` 把可写目录传给 node 脚本，
  避免它自己用 `os.tmpdir()` 踩同一个坑。

**教训**：凡是"用户点了没反应"的功能，先假设某处有未捕获异常，
而不是怀疑业务逻辑慢。

## 11. 出图进度显示怎么做的

脚本本身跑 13-20 秒但**中途完全静默**，用户会以为卡死。

做法：
1. `render_orbat.js` / `cdp.js` 输出带前缀的阶段标记：
   `[stage] 启动浏览器`、`[wait] 站点初始化 等待中 25s/120s`、`SVG_FILE`、`PNG_FILE`。
2. `waitFor()` 增加心跳：每 5 秒打印一次已等待时长，避免长等待静默。
3. `OrbatRenderer.render()` 用 `LineSplitter` 逐行转发给 `onLog` 回调，同时写日志文件。
4. UI 把阶段标记映射成「阶段名 + 百分比」，配合 250ms 计时器显示耗时，
   并在面板里滚动显示最近几行有效输出（滤掉 glyph / pageerror 噪音）。

进度是**真实的**：百分比只在收到对应阶段标记时前进，不做假动画。
